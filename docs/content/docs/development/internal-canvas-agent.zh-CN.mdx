# 应用内置画布 Agent

右侧画布 Agent 直接运行在 Infinite Canvas 前端中，使用配置中心当前文本模型所属渠道的接口地址、API Key 和独立 Agent 协议，不再依赖 Codex、MCP 或本机 Canvas Agent 服务。

## 协议与执行流程

每个模型渠道可以独立选择 `Responses API` 或 `Chat Completions`。两种适配只负责把各自的流式响应归一为文本、工具调用、用量和错误事件，共享同一套 Tool Loop。协议失败后不会自动切换，避免同一请求被重复执行和计费。

Tool Loop 会按“模型响应 → 白名单校验 → Zod 参数校验 → 权限及确认 → 画布执行 → 工具结果回传”循环，直到模型给出最终回复、用户停止或达到限制。默认限制为 12 个模型轮次、每轮 8 次工具调用、总计 32 次工具调用、单次 50 个画布操作和 50 个受影响节点。

## 画布一致性

每个写入和生成工具都必须携带当前 `projectId` 与 `expectedRevision`。项目切换或画布在读取后发生变化时，执行器会拒绝旧请求，要求模型重新读取。Agent 操作使用画布现有的 React 状态及正式历史记录，因此可以通过画布原有撤销功能恢复。

## 权限与安全边界

工具仅从固定注册表暴露，分为读取、画布写入和内容生成。读取默认开启；画布写入和生成默认允许但逐次确认，两类自动确认开关彼此独立。内置 Agent 不提供配置修改、任意网络请求、脚本执行或自定义 URL 工具。

API Key 只用于请求头，不进入模型上下文、工具结果或 Agent 日志。工具结果会对密钥形字段脱敏，并按长度限制截断。配置 JSON 默认不导出渠道 API Key 与 WebDAV 密码。

## 本地数据

会话消息、权限和限制使用 IndexedDB 持久化，并带独立的存储版本和协议版本。AbortController、确认回调与当前画布句柄只存在内存中。页面刷新或应用重启后，未完成请求会明确标记为已中断。

旧的本地 Agent、MCP 和 Codex 代码暂时保留用于迁移验收；在新链路完成手工验证且用户确认后再删除。
