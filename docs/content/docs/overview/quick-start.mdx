# Quick Start

To try the project, deploy or start the `web/` frontend.

## Deploy with Vercel

The root `vercel.json` builds `web/`. AI requests now use same-origin `/v1/` and `/v1beta/` endpoints. Vercel requires separately configured proxies; importing this repository does not establish access to the New API Docker network. Docker deployment is recommended below.

## Run locally

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas/web
bun install
bun run dev
```

Open `http://localhost:3000`.

Local Vite development also requires equivalent same-origin API proxies; this change does not configure a development proxy.

## Run with Docker

Follow [Docker Deployment](./docker) to configure the root `NEW_API_UPSTREAM` environment variable and confirm New API is attached to the external network first.

```bash
docker compose up -d --build
```

## First-time setup

- Open Settings and enter the API protocol, `API Key`, and model names. The provider URL is read-only and fixed to the current site origin.
- Open `/prompts` to fetch prompt repositories directly from the browser and cache them in IndexedDB.
- Configure WebDAV if you want to synchronize canvases, assets, and generation history across devices.

Canvas projects, My Assets, and the API key remain in the browser. Requests carry that key to the canvas origin, then Nginx forwards them to New API. Browser-to-canvas traffic may still pass through Cloudflare.
