# Pending Tests

## 视频网关 JSON 协议（待用户验证）

- 模型分流：配置自定义脚本时仍优先执行；无脚本时去除内部渠道前缀，只精确匹配三个 MiniMax H3 模型，其余模型一律走新协议，包括 apiFormat 为 Gemini 的模型。Agent 的画布生成工具和工作台命令沿用相同入口，不自行选择协议。
- H3 回归：三个模型的 duration、resolution、aspect_ratio 转换、reference_images/reference_audios、图片/音频/视频校验、原图床上传及专用参数限制保持；带 H3 关键词但非三个完整名称的模型使用通用参数。自定义脚本及其模板仍可使用自己的 multipart/Gemini 协议。
- 普通视频提交：POST /v1/videos，JSON 仅包含对外 model、prompt、数字 seconds、比例 aspect_ratio、清晰度 resolution 及非空 references；当前没有扩展参数，因此省略 metadata。不发送 duration、size、resolution_name、文件或 H3 引用字段。
- 参考素材：通用参数提供首尾帧和普通参考模式；前两张图片按 first_frame/last_frame，超过两张沿用自动普通参考，普通参考中的图片及视频/音频使用 reference，并保持各素材列表原有顺序。已有公网 URL 直接使用，视频生成由协议入口读取图片，已有公网 URL 不强制先转 Data URL；本地图片及视频复用 https://imageproxy.zhongzhuan.chat/api/upload，以 multipart file 字段上传且不带鉴权，成功后把公网 URL 放入 JSON；已有公网图片/视频 URL 时不重复上传。视频从现有本地媒体存储读取文件，不能把存储操作当作公网上传。普通模型的本地音频从现有浏览器媒体存储读取文件后，以 multipart file 字段上传到 https://files.sudashuiapi.com；已有公网音频 URL 直接使用。上传成功优先使用 proxyUrl，否则使用 url，并以 type=audio、role=reference 加入 JSON，保持音频原有顺序；音频上传失败不得创建生成任务。
- 新协议网关插件需配套：支持上述请求字段，references 为双方约定的网关扩展（不是 New API 官方通用标准）；返回网关 id，查询支持 queued/in_progress/completed/failed/unknown，成功用 result_url，失败用 error.code/error.message；无 result_url 时提供 /v1/videos/{id}/content 二进制。浏览器需能跨域查询和下载。上游格式转换在服务端插件完成，本次未实现服务端插件。
- 状态与成品：仅 completed 进入成品获取，URL 或 progress=100 不表示成功；result_url 下载不附带本站 API Key，无 URL 才带 Key 请求 content。完成标记与结果 URL 写入现有本地历史；下载或本地保存失败后只重新获取，不重新 POST。
- 任务恢复：画布和视频工作台保存 id 与明确的 h3/gateway/plugin 类型，不保存 API Key；刷新可继续未完成查询，停止等待的工作台记录可手动继续，画布未完成任务沿用刷新自动查询。旧格式任务不迁移、不猜测协议。
- 异常与重复提交：unknown 继续查询；网络异常、查询超时或本地等待结束保留 ID，不标为上游失败；界面区分“继续查询 / 重新获取”和“重新生成”，前者不 POST，只有明确重新生成才创建新任务。failed 明确表示上游失败并保留 ID；脚本一次性执行结果沿用现有行为，不承诺脚本可刷新恢复轮询。
- 停止说明：画布停止仅中断本地等待，不表示上游任务取消，没有调用取消接口。
- 视频等待时长调整：普通模型及 H3 视频工作台保持 2.5 秒间隔，最多查询 480 次（约 20 分钟加请求耗时）；H3 画布保持 10 秒间隔、最多 120 次。需验证 queued/in_progress/unknown 不会在原约 5 分钟时停止，达到新等待次数后保留任务 ID，手动继续查询不重新 POST。单次请求仍无显式超时；查询/下载异常立即停止本地等待，不新增自动重试、并发或上传大小限制；自定义脚本的超时逻辑不变。画布与工作台共用轮询实现。
- 上传接口专项实测（用户明确授权）：使用临时生成的 0.5 秒黑色视频 MP4（1671 字节）及静音 MP3（4615 字节）；MP4 上传 HTTP 200，返回地址下载 HTTP 200、video/mp4，SHA-256 与原文件一致；MP3 返回 HTTP 400，提示只支持图片或视频文件。该结果仅确认小样本的接口接受与下载，不代表所有视频格式、大文件、浏览器 CORS 或上游生成已验收。
- 音频上传服务专项实测（用户明确授权）：POST https://files.sudashuiapi.com，multipart file 字段；无鉴权返回 401，用户提供的零余额上传 Key 可成功上传 MP3（4615 字节）和 WAV（44178 字节），均返回 200。返回的 url 及 proxyUrl 不带 Key 下载均为 200、正确音频 MIME，SHA-256 与原样本一致。url 为约 2 小时有效的签名直链；proxyUrl 的长期有效性未验证。使用 localhost:3020 Origin 的上传响应及 OPTIONS 预检允许跨域与 Authorization，代理下载响应允许跨域；直链下载未返回允许跨域头。后续已按用户明确授权将独立上传专用 Key 写入公开前端，仅用于此音频上传接口，不使用生成 Key，不把上传 Key 写入任务历史或其他站点请求。该服务当前已接入普通视频模型；未新增前端大小限制、超时或自动重试，服务端拒绝时提示上传失败。图片/视频图床、H3 的音频公网 URL 限制及自定义脚本请求保持不变。需用户验收画布本地 MP3/WAV、多音频顺序、已有公网地址不重复上传、取消/鉴权失败不提交生成；真实页面上传、大文件、代理地址长期有效性和上游生成尚未验证。
- 未运行项目测试、语法检查、编译、构建或实际收费生成请求，需用户自行验收以上路径。


The current release needs manual verification in these areas:

- Local WebP previews: canvas image nodes and expanded alternatives, element lists, reference bars, asset cards/picker, and image/video workbench reference strips should use previews capped at 768px. Image Studio must retain concurrent batches and show preview thumbnails for results from every batch. Small images, remote-only images and custom covers should fall back correctly; full-size preview, high zoom, downloads, exports and generation references must use originals. Refresh, asset import and WebDAV restore should regenerate/reuse local previews; exported canvas/asset/history data and synced files must not contain preview blobs or URLs. Deletion must remove previews even while they are being generated. Automated checks cover source selection, proportions, cache reuse/deduplication, deletion during generation and replacement of originals.
- Image request timeout: built-in OpenAI generation/edit and Gemini image requests should fail after 10 minutes with a readable timeout message, leave the generating state and allow retry. Existing successful batch results must remain available. User cancellation must still report cancellation. This timeout is per HTTP request and does not override custom model scripts or video polling.
- Node overlay actions: download, duplicate, primary-image and primary-text controls should appear on hover or keyboard focus, remain clickable, and hide after leaving the node.
- Canvas drag and connections: drag single nodes, multiple selections and groups; confirm group highlighting, membership, release position and undo/redo. Pan/zoom a dense canvas and check that connections crossing the viewport remain visible even when both endpoints are offscreen; selection, context menus and connection creation must keep working.

- Image Studio concurrent tasks: the first Generate click should immediately create a history record and pending cards, then release the button. Further clicks should append images to the same title without replacing earlier results. New should start a separate title while previous tasks keep updating their original record, and running records should not be deletable.
- Video dimensions and duration: changing 480p/720p/1080p or the ratio should recompute width and height consistently. The workbench should keep compact resolution/ratio selectors and show a 4–30 second slider without custom dimensions.
- Built-in video requests: OpenAI-format channels should send `mode`, `first_frame`/`last_frame` or `image[]`, `generate_audio`, `watermark`, and reference videos/audio; Gemini-format channels should use `predictLongRunning` with frame or general references.
- Video generation mode: Video settings should offer First & last frame and General reference. One image is sent as the first frame, two images as first and last frames, and more than two images as general references.
- Agent generation flows and revisions: asking the Agent to connect an existing text node to a video generation node should reuse that node through `promptNodeId` and create only the config node and connection. Sequential writes emitted by the same Agent batch may reuse their original revision without conflict, while a real node or connection update outside that batch must still reject stale writes. Selection and viewport-only changes must not advance the canvas revision.
- Default text model: a fresh browser profile should show `gpt-5.6-terra` as the built-in channel's default text model and use it for new text conversations.
- Docker Compose deployment: after checking out the repository on Windows or Linux, `docker compose up -d --build` should build the current source instead of pulling the upstream image. The container should become healthy without restart loops; `/`, `/image`, `/video`, `/canvas`, and `/config` should return HTTP 200, and `APP_PORT` should override the default host port 3020.
- Official node plugin registry: opening the plugin manager should load Markdown, SVG, HTML, 3D Panorama, and Sticky Note from `onelxw/canvas-agent@plugins-dist`. Installation, enable/disable, and updates should continue working without requesting `basketikun/infinite-canvas@plugins-dist`.
- Canvas node creation menu: right-clicking blank canvas space should open the node creation menu at the click position, while double-clicking with the left button should not. Nodes and connections must retain their existing context menus, and neither reference-selection mode nor canvas overlays should accidentally open the creation menu.
- Workbench controls and navigation: My Canvases, Image Studio, Video Studio, Prompt Library, My Assets, and Settings must not show Docs or GitHub header actions. Image Studio should expose Quality, Ratio, and Image count as dropdowns without custom dimensions, with each ratio option showing its concrete resolution in smaller text. Video Studio should expose Quality, Ratio, and Seconds as dropdowns without custom quality or dimension inputs, with concrete resolutions shown in the ratio menu.
- Workbench scrollbars: the generation history, parameter editor, and result cards in both studios should hide native scrollbars. When content overflows, the arrowless 3px custom thumb should fade in while scrolling or dragging and automatically hide after roughly 0.9 seconds of inactivity. Wheel, trackpad, track clicks, and thumb dragging should all work. Hovering an empty reference area must not draw a simulated scrollbar; after enough references are added, only one real horizontal scrollbar should appear.
- Brand name and icon: the home page, canvas library, canvas page, browser title, and default export name should use “Infinite Dimension”; the top brand mark and browser tab should use the new black-backed, full-color infinity PNG and remain crisp and undistorted in light and dark themes.
- Home and provider settings: the home page and all standard page headers should no longer show Docs, GitHub, or the version entry, so release notes and update checks cannot be opened from the header. Settings → Providers should directly expose the provider name, API protocol, Canvas Agent protocol, API key, and model settings without add, delete, or secondary edit controls. The endpoint must remain read-only at `https://api.aiacg.de` after refresh, old configuration import, or legacy URL parameters, while retaining only the first old provider's key and models.
- Built-in Canvas Agent conversation history: after completing a conversation, New conversation should preserve the previous content in history. Entries should use the first user message as their title, show the updated time, support switching and deletion, survive refresh, and retain a pre-upgrade single conversation. Switching and deletion must be disabled while a run is active.
- Built-in Canvas Agent status and canvas navigation: “Thinking” should appear only while the latest model round is waiting for a response, then disappear when text or a tool operation starts and after completion. Tool status, summary, and the trailing disclosure arrow should remain on one line without a duplicate “View details” label. The canvas header should no longer show Docs, version, or GitHub, and the canvas menu should no longer contain Docs.
- Built-in Canvas Agent tool activity: completed read, write, delete, and generation calls should collapse to a one-line summary instead of exposing raw JSON in the conversation. Clicking the summary row or trailing arrow should expand and collapse formatted results, long content must not create page-level horizontal overflow, and both panel and detail scrollbars should be thin, borderless, and arrowless.
- Built-in Canvas Agent: without starting Canvas Agent, Codex, or MCP, the right panel should use the configured text model. Responses and Chat Completions providers should each stream text, read canvas state, modify a node, and continue after tool output. Protocol errors must not auto-fallback.
- Built-in Agent safety and consistency: canvas writes and generation should prompt independently by default; rejection must prevent execution. Project switches or manual edits before confirmation must trigger project/revision conflicts. Stop and refresh must prevent further tool execution, while duplicate call IDs, unregistered tools, extra parameters, and oversized batches are rejected.
- Built-in Agent local data: completed messages and permissions should restore from IndexedDB after refresh, running requests should become interrupted, and exported configuration must exclude provider API keys and the WebDAV password.
- Documentation navigation and page contents: at phone width, opening the documentation sidebar should show the current section and its description at the top. Expanding it should allow switching among Overview, Canvas Guide, Development, Progress, Business, and Support; the selected section and page list should update together while the desktop top tabs remain unchanged. At widths of 960px and above, a table of contents with hierarchical track lines should appear to the right of the article, support heading navigation, and highlight the current heading while scrolling; narrower layouts should keep the top collapsible contents control.
- Canvas Agent generation-flow references: when a generation prompt contains only `@[node:...]` references already passed through `referenceNodeIds`, the existing text, image, video, audio, or group nodes should connect directly to the generated config node without creating a duplicate prompt text node; prompts containing ordinary prose should continue creating their own prompt text node.
- Video frame capture: right-clicking a video node with content should show Capture first frame, Capture last frame, and Capture current frame. Each action should create and select a proportional image node to the right, connect the video to the image, use the player's visible position for the current frame, and leave the original playback position unchanged.
- Text nodes: the Generate button should no longer appear in the upper-right corner of the node body, and text should use the full content area. The image-generation action in the hover toolbar should continue to create a generation configuration.
- Multi-text generation: requesting more than one result should create one text-result node and one source connection. Its upper-right count should expand all successful alternatives like a multi-image node; setting an alternative as primary should immediately replace the body while retaining the previous primary, and edits to any primary text should remain when switching away and back.
- Group references: group nodes should use a transparent, lightweight border and title treatment and expose a source handle on the right. Connecting a group to a generation node should include every populated image, video, audio, text, and reference-capable extension node inside it. Regular prompt mentions should list the group's resources, while the generation-config composer should allow selecting the whole group with one `@`; resources referenced both individually and through the group must be sent only once.
- Group selected nodes: after selecting two or more nodes, a rounded dashed bound should wrap the whole selection, with Group above it. It wraps those nodes in a group without moving them, then selects the new group. Selecting a group should allow Ungroup from the hover toolbar, context menu, or `Ctrl/Cmd+Shift+G`. Images and videos should use thumbnails with hover previews, while text, audio, and extension nodes show their matching type. The plus button should enter canvas selection for adding multiple valid references. - Canvas navigation: the canvas should open in Move mode by default, and the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should drag elements directly and pan only when dragging the blank background. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. - Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability: importing an image should open its prompt panel, resizing it immediately from any corner should temporarily hide the panel, remain smooth without flashing or triggering a maximum update depth error, and restore the panel after release. Prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration should continue to work.
